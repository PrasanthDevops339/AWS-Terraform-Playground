## 4. Org Guard Rule Implementation

### 4.1 Source of Truth

The production org pack is declared in:

- `custom-config-rules/environments/prd/cpack_encryption.tf`

The module used by both regions is:

- `custom-config-rules/modules/conformance_pack/`

### 4.2 Render Flow

The render flow is:

1. `environments/prd/cpack_encryption.tf` defines `policy_rules_list`, `lambda_rules_list`, and the pack name.
2. `modules/conformance_pack/cpack_template.tf` reads the referenced Guard file with `file("../../policies/...")`.
3. `modules/conformance_pack/templates/guard_template.yml` or `lambda_template.yml` renders the CloudFormation YAML block.
4. `modules/conformance_pack/cpack_organization.tf` submits the final YAML as `aws_config_organization_conformance_pack`.

### 4.3 Naming Pattern

The conformance pack name is generated by:

- `modules/conformance_pack/cpack_organization.tf`

Pattern:

```text
<account_alias>-<cpack_name>
```

For this implementation:

```text
<account_alias>-encryption-validation
```

Each rendered rule name inside the pack is generated by:

- `modules/conformance_pack/cpack_template.tf`

Pattern:

```text
<account_alias>-<config_rule_name><optional-random-id>
```

The random suffix only appears in non-prod pre-dev patterns.

## 5. Guard Rules by Service

### 5.1 EBS

Active file:

- `custom-config-rules/policies/ebs-is-encrypted/ebs-is-encrypted-2026-01-09.guard`

Current policy text:

```guard
rule ebsIsEncrypted when resourceType == "AWS::EC2::Volume" {
    configuration.encrypted == true <<EBS Volumes must be encrypted>>
}
```

Important mismatch:

- `environments/prd/cpack_encryption.tf` scopes EBS to `AWS::EC2::Volume` and `AWS::EC2::Snapshot`
- the Guard file itself only checks `AWS::EC2::Volume`

Operational consequence:

- snapshot compliance is not currently enforced by the actual Guard logic

### 5.2 SQS

Production file:

- `custom-config-rules/policies/sqs-is-encrypted/sqs-is-encrypted-2025-10-30.guard`

Current production logic:

```guard
rule sqsIsEncrypted when resourceType == "AWS::SQS::Queue" {
    configuration.SqsManagedSseEnabled == true
        or configuration.KmsMasterKeyId exists
    <<SQS must be encrypted with SSE-SQS or SSE-KMS at the time of creation>>
}
```

Staging file:

- `custom-config-rules/policies/sqs-is-encrypted/sqs-is-encrypted-2026-01-27.guard`

Important difference:

- the staging file uses different property casing and a different annotation string

Operational consequence:

- if production is upgraded to `2026-01-27`, CCOPS `Annotations` filters must be reviewed in the same change

### 5.3 EFS

Active file:

- `custom-config-rules/policies/efs-is-encrypted/efs-is-encrypted-2025-10-30.guard`

Logic:

```guard
rule efsIsEncrypted when resourceType == "AWS::EFS::FileSystem" {
    configuration.Encrypted == true <<EFS's must be encrypted>>
}
```

This is the at-rest-only check.

## 6. EFS TLS Lambda Through AFT

### 6.1 Control Files

- `terraform-aft-account-customizations/exceptions/terraform/aft-provider.tf`
- `terraform-aft-account-customizations/exceptions/terraform/variables.tf`
- `terraform-aft-account-customizations/exceptions/terraform/lambda-rules-enforcement.tf`
- `terraform-aft-account-customizations/exceptions/terraform/conformance-pack-templates.tf`
- `terraform-aft-account-customizations/modules/lambda/*`
- `terraform-aft-account-customizations/modules/scripts/efs-tls-enforcement/efs_tls_enforcement.py`
- `terraform-aft-account-customizations/modules/policy-files/efs_tls_compliance.json`

### 6.2 Deployment Path

The AFT deployment path is:

1. `aft-provider.tf` sets the provider region from `var.region`.
2. `variables.tf` defaults that region to `us-east-1`.
3. `lambda-rules-enforcement.tf` instantiates `module "efs_tls_enforcement_compliance"`.
4. That module packages the Python code from `modules/scripts/efs-tls-enforcement/`.
5. `conformance-pack-templates.tf` renders the account-level rule and `aws_config_conformance_pack`.

### 6.3 Runtime Names

Lambda function naming pattern from `modules/lambda/main.tf`:

```text
<account_alias>-efs-tls-enforcement-function
```

Config rule naming pattern from `exceptions/terraform/conformance-pack-templates.tf`:

```text
efstlsenforcement_<account_id>
```

Conformance pack name:

```text
Lambdarulesconformancepack
```

### 6.4 IAM Permissions

The Lambda inline policy template includes:

- `config:PutEvaluations`
- CloudWatch Logs permissions
- `elasticfilesystem:DescribeFileSystemPolicy`
- `elasticfilesystem:DescribeFileSystems`
- `elasticfilesystem:DescribeReplicationConfigurations`

Source:

- `terraform-aft-account-customizations/modules/policy-files/efs_tls_compliance.json`

### 6.5 Compliance Logic

The Lambda returns `NON_COMPLIANT` when:

- the file system has no policy
- the policy does not deny non-TLS access for EFS client actions
- the file system lookup fails
- policy evaluation throws an exception

The Lambda returns `NOT_APPLICABLE` when:

- the resource is deleted
- the file system is an EFS replication destination

Primary annotations emitted by the Lambda include:

- `EFS file system has no policy defined`
- `EFS file system has no policy - TLS enforcement not configured`
- `EFS policy does not enforce TLS for EFS client actions (ClientMount/ClientWrite/ClientRootAccess)`

## 8. CCOPS Rule Storage and Processing

### 8.1 DynamoDB Storage

Source file:

- `cloud-ops-governance-platform/dynamo/rules.json`

Loader:

- `cloud-ops-governance-platform/dynamodb.tf`

The JSON fields `actions_policy` and `ingest_policy` are stored as stringified JSON values in DynamoDB.

Table:

```text
ccops-policy-engine-rules
```

Keys:

- hash key: `source`
- range key: `id`

### 8.2 Upstream Aggregation Flow

The matching flow is:

1. `cloud-ops-ecr-image-builder/scripts/config_aggregator.py` queries DynamoDB for enabled `aws_config` rules.
2. It reads the stringified `ingest_policy`.
3. It uses:
   - `ResourceTypes`
   - `Rules`
   - `Annotations`
   - `ComplianceType`
4. It writes one CSV per account and per rule.
5. `cloud-ops-governance-platform/scripts/complianceIngestLambda/compliance_ingest.py` loads those CSV rows into MySQL.
6. `cloud-ops-governance-platform/scripts/complianceRulesExecutionLambda/complianceRulesExecution.py` groups rows by `ruleId`, writes processed CSVs, and creates `actions` rows.
7. `cloud-ops-governance-platform/scripts/serviceNowEventManagerLambda/servicenow_eventmanager.py` reads the rule's `actions_policy` and creates or updates ServiceNow incidents.

### 8.3 Why Rule and Annotation Matching Must Use Stable Substrings

Config rule names differ by deployment path:

- Guard rules inside conformance packs are emitted as `<account_alias>-<config_rule_name>`
- AFT Lambda rules are emitted as `efstlsenforcement_<account_id>`

Because of that, CCOPS should match stable substrings, not a full generated name.

The same rule applies to annotations:

- use stable substrings such as `EFS file system has no policy`
- do not rely on the full sentence if the source implementation may change wording later

## 11. Known Mismatches and Caveats

| Area | Caveat |
| --- | --- |
| EBS Guard scope | Terraform says volume plus snapshot; Guard file checks volume only |
| SQS prod vs dev | Different Guard file versions and annotation messages are in use |
| AFT region model | AFT customization defaults to `us-east-1`; it is not automatically multi-region like the org pack |
| OPA registry integrity | `policies.hcl` has references that are not all backed by real policy files |
| CCOPS matching | Matching depends on stable substrings; changing annotation wording can silently break incident generation |
